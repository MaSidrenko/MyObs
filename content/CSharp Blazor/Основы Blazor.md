# Blazor - это
  Blazor UI-Фреймворк ([[Framework]]) для создания интерактивных приложений, которые могут работать как на стороне сервера, так и на стороне клиента, на платформе .NET. В качестве языка программирования применяется C#, вместо JavaScript. А для описания визуального интерфейса используются стандартные HTML и CSS.
  Blazor развивается как opensource проект, исходный код которого можно найти на GitHub: [https://github.com/dotnet/aspnetcore/tree/master/src/Components](https://github.com/dotnet/aspnetcore/tree/master/src/Components)
  Blazor предоставляет следующие преимущества: 
	1. Написание кода веб-приложений с помощью C# вместо JavaSctript 
	2. Использование возможностей экосистемы .NET, в частности библиотек .NET при создании приложений, безопасности и производительности платформы .NET
	3. Клиентская и серверная части приложения могут использовать общую логику
	4. Использование Visual Studio в качестве инструмента для разработки, который имеет встроенные шаблоны для упрощения создания приложения.
 Функционально на текущий момент Blazor подразделяется на несколько подсистем:
	1. Blazor Server: позволяет создавать серверные приложения и поддерживается ASP.NET 
	2. Blazor WebAssembly ([[WebAssembly]]): позволяет создавать одностраничные интерактивные приложения клиентской стороны, которые запускаются в браузере пользователя и работают с помощью технологии WebAssembly
	3. Blazor Hybrid: позволяет создавать десктопные и мобильные приложения поверх технологии .NET MAUI 
# Blazor Wasm
Долгое время написание клиентских веб-приложений было уделом языка JS. Внедрение Wasm изменило ситуацию. И технология Blazor WebAssembly позволяет создавать приложения на ЯП C#, которые запускаются и отрабатывают в браузере пользователя благодаря технологии Wasm. При построении и запуске приложения Blazor Wasm файлы с кодом C# и Razor компилируются в сборки .NET Затем Blazor WebAssembly(А точнее скрипт `blazor.webassembly.js`)  загружает среду выполнения .NET, сборки и их зависимости и настраивает среду выполнения .NET, сборки и их зависимости и настраивать среду выполнения .NET для выполнения сборок. Посредством взаимодействия с JavaScript фреймворк Blazor WebAssembly может обращаться к DOM и API браузера.
### Преимущества Blazor Wasm
Эта модель имеет ряд преимуществ, к примеру так, как Blazor Wasm, не зависит от сервера, то все необходимые файлы среды выполнения .NET и загружаемых сборок могут кэшироваться в браузере и работать без доступа к сети. Так же из-за того что приложение полностью работает на стороне клиента, то снижается нагрузка на сервер.
### Ограничения Blazor Wasm
Так же Blazor Wasm имеет ряд ограничений. Например, браузер должен поддерживать технологию WebAssembly - на данный момент последние версии распространённых браузеров (Google Chrome, Mozilla Firefox, Opera, Microsoft Edge, Yandex Browser) поддерживают эту технологии. Однако их более старые версии, либо Internet Explorer не имеют подобной поддержки. Так же браузеру необходимо загрузить файлы большого размера, что увеличивает нагрузку на сеть и время загрузку. Так же поскольку файлы приложения доступны пользователю, то нивелируется возможность скрыть какой-нибудь код, который представляет коммерческую ценность.
# Blazor Server
В Blazor Server приложение отрабатывает на стороне сервера. Обновление элементов пользовательского интерфейса, обработка событий, вызовы JavaScript на клиентской стороне осуществляется посредством взаимодействия сервера и клиента через SignalR.

То есть когда пользователь взаимодействует с приложением в браузере, (например нажимает на кнопку), то клиентская сторона посылает на сервер информацию о событии, сервер обрабатывает полученную информацию и посылает клиенту в ответ инструкции, как необходимо обновить элементы интерфейса. 
### Преимущества Blazor Server
Поскольку большая часть логики приложения сосредоточена на стороне сервера, то все загружаемые клиентом файлы имеют гораздо меньший размер по сравнению с Blazor Wasm. Так же нет ограничений по браузеру, и может работать с браузерами которые не поддерживают технологию WebAssembly.
### Недостатки Blazor Server
В то же время для работы приложения необходима постоянная поддержка сетевого подключения. Так же чем больше пользователей , тем больше нагрузка на сервер. Также задержки в сети могу оказывать негативное воздействие, к примеру: при задержки в более чем 200 МС интерфейс становится гораздо менее отзывчивым.
