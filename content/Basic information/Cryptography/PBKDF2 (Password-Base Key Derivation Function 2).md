PBKDF2 - это криптографическая ф-ция, которая использует для преобразования пароля в стойкий ключ ([[Secure Key]]).
Зачем нужен PBKDF2?:
	1. Пароли слишком короткие и легко подбираются;
	2. Обычное хеширование ([[Hash]]]) (К примеру SHA-256(Password)) слишком быстрое - можно легко сделать миллиарды проверок в секунду;
	3. PBKDF2 замедляет процесс подбора, делая атаку перебором очень дорогой;
# Как работает PBKDF2
1. Добавляет [[Salt]] к паролю (Что бы одинаковые пароли давали разные [[Hash]]'ы);
2. Много раз хеширует ([[Hash]]) пароль (N итераций, к примеру 100 000);
3. Выдаёт стойкий ключ ([[Secure Key]]) (256 бит), который можно использовать в AES.
## Алгоритм PBKDF2
1. Берём пароль и [[Salt]];
2. Выполняем много итераций хеширования ([[Hash]]) ([[HMAC-SHA256]]);
3. Получаем криптографический стойкий ключ ([[Secure Key]]);
### Пример работы

```
string password = "MySecurePassword";
byte[] salt = GenerateSalt();
byte[] key = DeriveKey(password, salt, 32, 100000);

private static byte(string password, byte[] salt, int keySize = 32, int iterations = 100000)
	{
		using (var pbkdf2 = new Rfc2898DeriveBytes(password, salt, iterations, HashAlgorithmName.SHA256))
		{
			return pbkdf2.GetBytes(keySize);
		}
	}
```
#### Что здесь происходит?
1. Пароль "MySecurePassword" и соль передаются в PBKDF2;
2. PBKDF2 100000 раз выполняет HMAC-SHA256(password + [[Salt]]);
3. В итоге получаем 256-битный (32  байта) ключ который можно использовать в AES ([[AES]]);
# Защита от атак
PBKDF2 делает атаки медленными. Без PBKDF2, можно подбирать пароли миллиардами в секунду. PBKDF2 замедляет процесс например:
	Обычное SHA-256 --> 100 000 000 000 проверок/сек;
	PBKDF2(100 000 итераций) --> 1000 проверок/сек;
# Где можно применить?
1. Шифрование данных (AES - 256) генерация ключа из пароля;
2. Хранение паролей - в базах данных вместо обычных хешей([[Hash]]);
3. Аутентификация - используется в Wi-Fi WPA2, ButLocker, LastPass, KeyPass;
