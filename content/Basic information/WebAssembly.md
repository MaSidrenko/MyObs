# Что такое WebAssembly
WebAssembly(Wasm) - это бинарный формат запускаемый в браузере, виртуальная машина. и результат компиляции с ЯП высокого уровня.
Wasm это не ЯП, скорее это байт-код. Не связан с вебом, может запускаться и вне веба
![[Что такое Wasm.png]]
Создатели Wasm руководствовались следующими целями:
	1. Кросс-платформенность;
	2. Компактность;
	3. Скорость; 
# Поддержка языков
1.С/С++ - Через [Emscripten](https://emscripten.org/), очень хорошая поддержка;
2. Rust - поддержка WASM появилась очень давно, экосистема вокруг WASM, строится во многом на основе Rust;
3. Java - через TeaVM, JWebAssembly, Bytecoder - на экспериментальном уровне;
4. kotlin - есть поддержка в Kotlin/Native через LLVM backend  - экспериментальная;	
5. Go;
6. C# - через [Blazor](http://blazor.net/) (mono) и в будущем на [Uno Platform](https://platform.uno/);
7. TypeScript - через [AssemblyScript](https://docs.assemblyscript.org/);
# Сценарии использования
Уже сейчас Wasm активно применяется в следующих областях:
	1. Игры, игровые движки физики, VR/AR - например, [Godot](https://godotengine.org/), [Doom 3](https://wasm.continuation-labs.com/d3demo/);
	2. Эмуляторы, виртуальные машины - например, [DOSBox](https://github.com/dreamlayers/em-dosbox);
	3. Графические/3D редакторы - [Figma](https://www.figma.com/blog/webassembly-cut-figmas-load-time-by-3x/), [AutoCAD](https://www.infoq.com/presentations/autocad-webassembly/);
	4.  Веб-клиенты для финансовых торговых площадок;
	5. Кодеки и фильтры аудио/видео - например, [ffmpeg](https://habr.com/ru/post/473098/);
	6. Базы данных - например, SQLite;
### Другие сценарии использования 
1. Progressive web application (PWA);
2. Распознавание натренированной нейронной сетью;
# Производительность 
Производительность Wasm была одним из его главных факторов.
В сравнении с JavaScript, получается в среднем Wasm быстрее, но в каждом частном случае нужно делать сравнение JS/Wasm, потому что может получится, как и во много раз лучше, так и в несколько раз хуже, так же на производительность может вилять от браузера. Пиковая производительность JS и Wasm одинакова, поскольку оба в итоге превращаются в родной код процессора. Но JS гораздо легче теряет в производительность, а Wasm обеспечивает более "ровный" подход.
Как правило Wasm хорошо показывает себя на объёмных вычислениях. Там где много операций с памятью, Wasm проигрывает.
# Wasm вне браузера
 Wasm по сути никак не связан с вебом, это просто виртуальная машина. А значит, его вполне можно использовать и вне веба
Сейчас видны следующие несколько сценариев использования Wasm вне браузера:
	1. Node.js - в его основе лежит движок V8, который поддерживает Wasm;
	2. Отдельное консольное приложения, код приложения используется в Wasm VM - примеры таких runtime: [wasmtime](https://github.com/bytecodealliance/wasmtime), wasmer;
	3. Wasm VM(VM - Virtual Machine) используется как библиотека из других языков - например [wasmer](https://github.com/wasmerio/wasmer)позволяет вызвать себя из десятка различных языков
