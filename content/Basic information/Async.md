Асинхронное программирование - концепция программирования, при которой результат выполнения ф-ции доступен спустя некоторое время в виде асинхронного (нарушающего стандартный порядок выполнения) вызова. Запуск длительных операций происходит без ожидания их завершения и не блокирует дальнейшее выполнение программы![[asynchr-1-1616163.png]]
## Когда использовать Асинхронность
Использование асинхронного программирования повышает производительность, отзывчивость и стабильность приложений. Используется там где нужно выполнять длительные операции без заморозки основного потока выполнения программы.
1. Веб-разработка: асинхронность помогать делать сайты и веб-приложения быстрыми и "отзывчивыми". Например лента новостей в соцсетях загружаются асинхронно. Вместо того чтобы ждать, пока все данные загрузятся, страница отображается сразу, а данные подтягиваются по мере готовности;
2. При работе с файлами асинхронность помогать избежать заморозки интерфейса при выполнении длительных операций, таких как чтение или запись больших файлов.
3. Важна при работе с сетью, где задержки и время ответа могут варьироваться;
4. Приложения для видеозвонков используют асинхронные методы для передачи данных в реальном времени
## Как реализована Асинхронность
Асинхронность реализуется на нескольких уровнях - от написания кода до выполнения инструкций процессором:
1. Уровень когда. Разработчики используют ЯП и библиотеки для создания асинхронного кода;
2. Уровень рантайма. Рантайм, или среда выполнения кода, интерпретирует асинхронный коды и управляет задачами. Асинхронные задачи добавляются в очередь, и событийный цикл следит за их выполнением, передавая управление соответствующим обработчикам, когда задачи завершаются
3. Уровень ОС. У ОС есть планировщик, который распределяет процессорное время между различными задачами Асинхронные задачи могут быть помещены в очереди ОС, чтобы быть выполненными, когда процессор доступен. Например когда данные готовы для чтения с диска, прерывание сообщает ОС, что выполнение задачи может быть продолжено.
4. Уровень Железа. Процессор может переключаться между задачами. Это позволяет выполнять другие задачи, пока одна операция (например ожидание данных из сети) ждёт завершения. Некоторые операции вроде чтения и записи данных могут использовать прямой доступ к памяти и таким образом освобождать процессор для других задач.
## Асинхронность в .NET
1. EAP (Event-based Asynchronous Pattern) - подход основан на событиях, которые срабатывают по завершении операции и обычного метода, вызывающего эту операцию
2. APM (Asynchronous Programming Model) - основан на 2 методах. Метод BeginSmth возвращает интерфейс IAsyncResult. Метод EndSmth принимает IAsyncResult (если к моменту вызова EndSmth операция не завершена, поток блокируется); 
3. TAP (Task-based Asynchronous Pattern) - async/await (эти ключевые слова появились уже после появления подхода и типов Task и Task<TResult>, но они значительно улучшили эту концепцию)(Самый популярный/успешный/используемый подход!!!!);
