1. Не произошло race condition (Race condition - это ошибка многопоточности, когда два или более потоков обращаются к общему ресурсу одновременно и результат зависит от порядка их выполнения. Порядок непредсказуем -> возникают баги). Пример из жизни: два кассира одновременно выдают сдачу из одного ящика - каждый берёт деньги, думая что он первый -> сумма получается неправильной.

Пример из жизни: Поток А держит ключ от комнаты  1 и ждёт ключ от комнаты 2. А поток В наоборот, держит ключ от комнаты 2 и ждёт ключ от комнаты 1

3. Starvation (Голодание). Когда один или несколько потоков постоянно откладываются и не получают доступ к ресурсу, хотя не заблокированы. Их "Обходят другие приоритетные потоки". Пример из жизни: Один человек стоит в очереди, но другие постоянно "Пролезают" без очереди. Он стоит вечно хоть очередь движется

Высокоприоритетный поток может так сильно загружать CPU, что низкоприоритетный почти не выполнится

Как избавится от starvation?
1. Не использовать приоритеты потоков(Почти всегда)
2. Использовать механизмы синхронизации
	1. SemaphoreSlim
	2. ConcurrentQueue
	3. Разделять большие задачи на более мелкие
	4. Использовать Task Scheduler из TPL вместо ручного создания потоков

# Мьютекс (Mutex)
Мьютекс - это объект синхронизации позволяющий только одному потоку владеть ресурсом
## Характеристики: 
1. Обеспечивает взаимоисключение (mutal exclusion);
2. Может быть межпроцессным(Доступен разным процессам)
3. Поток, который захватил мьютекс, должен его отпустить
4. Если поток удерживающий мьютекс, заверщится - ОС освободит мьютекс
## Использование:
Подходит для критических ресурсов, которые должны использоваться строго по одному потоку:
1. Запись в файл;
2. Разделяемые структуры данных;
3. Операции с устройствами;

# Семафор(Semaphore)
Семафор - объект, который ограничивает количество потоков, одновременно имеющих доступ к ресурсу
## Характеристики
1. Имеет счётчик, например N = 5;
2. Одновременно могу войти не более N потоков;
3. Когда поток выходит он увеличивает счётчик;
4. Может быть межпроцессным;
## Виды семафоров
1. Двоичный семафор - аналог мьютекса;
2. Счетный семафор - с числом > 1;
## Использование
Применяют когда нужно ограничить количество одновременных пользователей ресурса:
1. Пул соединений к БД;
2. Ограничение числа рабочих потоков;
3. Доступ к пулу файлов или объектов

# События(Event)
Событие - объект, который используется для уведомления одного или нескольких потоков о наступлении определённого состояния
## Характеристики
1. Бывают двух типов:
	1. Auto-reset event - автоматически сбрасывается после пробуждения одного потока 
	2. Manual-reset event - вручную сбрасывается после установки
2. Потоки могу ждать события через WaitForSingleObject
## Использование
Применяется для сигнализации между потоками:
1. Сообщить, что данные готовы;
2. Уведомить рабочий поток остановиться;
3. Синхронизация "Производитель - потребитель";
4. Завершение асинхронной операции;

# Критические секции (Critial Section)
Механизм синхронизации только внутри одного процесса
## Характеристики
1. Очень быстрая быстрее мьютексов
2. Не может использоваться между процессами
3. Предназначена для защиты небольших областей кода
## Использование
### Защита:
1. Структуры данных в памяти (vector, map);
2. Счетчиков;
3. Списков
4. Общих переменных

# Взаимоисключающий доступ (Mutal Exclusion)
Это общая концепция, а мьютекс - её конкретная реализация 
## Mutual Exclusion - означает, что:
1. Только 1 поток может выполнять защищённый код;
2. Остальные блокируются до освобождения ресурса
## Реализуются через:
1. Мьютекс
2. Критическую секцию (lock, monitor)
3. Двоичный семафор
