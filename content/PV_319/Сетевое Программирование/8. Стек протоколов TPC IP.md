Состоит из четырех уровней, которые нумеруются сверху вниз:
 I - Application(Прикладной);
 II - Transport(Основной);  
 III - Network(Сетевой) Internework;
 IV - Network Interfaces(Сетевые интерфейсы);
 Каждый из этих уровней выполняет обязанности, одного или нескольких уровней модели OSI([[7. Модели сетевого взаимодействия]])![[TCP IP.png]]
Касательно прикладного уровня протокол DHCP(Dynamic Host Configuration Protocol(Протокол Динамической Настройки Узлов)), отвечает за выдачу IP-адресов узлам сети, и других настроек протокола IP, кроме IP-адреса, это ещё маска подсети, основной шлюз, DNS etc. Протокол DHCP так же может выдавать имя загрузочного файла и адрес загрузочного сервера, для загрузки ОС по сети. (ПЕРЕСМОТРЕТЬ!) UDP-67 и UDP-68. Протокол DHCP произошел от протокола Bootp(Старая версия DHCP). 
# Протоколы  прикладного уровня
## Telnet
Это протокол удаленного управления, который позволяет выполнять команды, на удалённом ПК через LAN или Enternet. Главным недостатком протокола Telnet, является то, что он передает данные по открытым каналам связи, включая логины, пароли и вообще всю информацию. Работает по 23 порту протокола. Недостатки  протокола Telnet, устраняет SSH(Secrue Shell), так же как и Tellnet, позволяет управлять (Пересмотреть!!!), но абсолютно всю информацию передает по зашифрованным каналам связи. SSH работает по 22 порту TCP
## [[DNS]]
Позволяет присваивать узлам(А точнее IP-адресам) иерархические символьные имена. FQDN (Fully Qualified Domain Name(Полностью определенное доменной имя)). На транспортном уровне протокол DNS используется 53 UDP и TCP
## NetBIOS
Это набор протоколов в частности он включает протоколы для разрешения имен, в отличии от DNS netBIOS использует как плоские имена. Такие имена часто используют в LAN. Кроме плоского наименования, NetBIOS так же позволяет использовать файловую систему другого пк как свою собственную файловую систему, через локальную сеть. NetBIOS как правило используется в сетях Windows как основной протокол обмена файлами. Протокол NetBIOS в UNIX системах ещё называют SMB(Samba)
## NFS(Network File System)
Аналог протокола NetBIOS в UNIX системах, так же позволяет использовать файловую систему другого компьютера использовать как свою локальную файловую систему. 
NFS и NetBIOS - это не маршрутизируемые протоколы, т.е., они могут работать только в пределах одной локальной сети (Без выхода в Интернет). 
Для обмена файлами так же существуют протоколы  
## File Transfer Protocol
Протокол передачи файлов. Работает по протоколу TCP-21, может передавать данные как в локальной сети так и в интернете 
## Trivial File Transfer Protocol 
Простой протокол передачи файлов. Работает по протоколу UDP-67. Как правило используется только в локальных сетях. И предназначен для передачи образов ОС, резервных копий конфигураций. При установке или загрузке ОС через сеть, передача данных ОС по протоколу TFTP
## [[HTTP]]
Hyper-Text Transfer Protocol (Протокол передачи гипертекста). Используется для общения браузера с веб-серверов. Работает по протоколу TCP-80.
## HTTPS
HTTP Secure в отличии от протокола HTTP, который передает данные в открытом виде, он шифрует передаваемые данные при помощи протоколов SSL/TLS - Sequre Socket Layer/Transport Layer Security. Работает по TCp-443. Так же используется для шифрования почтовых сообщений

# Протоколы транспортного уровня
На транспортном уровне работает всего два основных протокола TCP и UDP.
## TCP
Transmission Control Protoloc(Протокол управления передачей). Работает с установлением виртуальных соединений, благодаря чему обеспечивает надежную доставку данных, то есть выполняет обязанности сеансового уровня модели OSI, но вносит определенную задержку при передачи данных, а так же тратит определенную часть пропускной способности, на контроль доставки данных. 
Протокол TCP используется для передачи данных, чувствительных к потерям (Как правило файлы). Протокол TCP описан в нормативном документе RFC-793
## UDP
User Datagram Protocol (протокол пользовательских дейтаграмм). Работает без установления виртуальных соединений, по этому не обеспечивает ни какой надежности доставки данных, но лучше подходит для передачи трафика реального времени. Таких как аудио или видео. Описан в нормативной документе RFC-768

Основной задачей протоколов транспортного уровня, является доставка данных до приложения в пределах узла. Для этого они, используют номера портов. Порт(Port) - это число длинной два байта означающие номер приложения прослущуюшего сеть. Всего портов 65 536. Номер порта, это свое рода адрес приложения в пределах узла. Номера портов с 0 по 1023, ещё называют Well known ports или обще известные порты. Эти порты используют стандартные приложения такие как Web-сервер SSH-сервер. Well know ports(или обще известные порты) всегда можно найти в файле в ОС Windows (C:\Windows\System32\drivers\etc\services) 
# Сетевой уровень
Основным протоколом является IP - Internet Protocol (Протокол межсетевого взаимодействия). 
## IP
Главной задачей протокола IP является доставка данных до узла назначения в составной сети. Протокол IP работает как на оконечных узлах так и на маршрутизаторах. Протокол IP всегда перенаправляет пакет, следующему маршрутизатору, который на один шаг ближе к сети назначения чем отправитель. Для того что бы понять на какой интерфейс переслать пакет, протокол IP использует таблицу маршрутизации. Она есть как на оконечных узлах, так и маршрутизаторах. Если протокол IP не знает какому следующему маршрутизатору переслать пакет, он отправляет на маршрут по умолчанию (Default Route). Протокол IP описан в нормативном документе RFC-791. 
Он никоем образом не может обходится без протокола ARP - Address Resilution Protocol(Протокол разрешения адресов).
## ARP 
Находит по указанному MAC-адресу, находит MAC-адрес узла. Этот MAC-адрес вкладывается в заголовок Ethernet кадра, а затем используется коммутатором, что бы переслать на советующий порт. Протокол ARP, работает только в пределах локальной сети (Одного широковещательного домена). Протокол ARP описан в документе RFC-826. Использует широковещательные сообщения для поиска MAC-адресов (Boradcat Message). В любой ОС, так же есть ARP кэш, которые хранит недавно найденные MAC-адреса. В ОС Windwos время жизни ARP кэша составляет две минуты, если за эти две минуты, не было обращения она удаляется. Отобразить ARP кэш можно командой arp -a. 
## ICMP
Internet Control Message Protocol - протокол межсетевых управляющих сообщений. Описан в RFC-792 и предназначен для диагностики сети. И отправке сообщений об ошибках. Команды ping и tacert используют ICMP сообщения. 
## Протоколы маршрутизации
К ним относятся:
1. RIP (Routing Information Protocol)
2. IGRP -(Internet Gateway Routing Protocol)
3. EIGRP - (Extended IGRP)
4. OSFP - (Open Shortesst Path First)
5. BGP - (Dorder Gateway Protocol)
Существует ошибочное мнение о том, что протоколы маршрутизации, перенаправляют пакеты, до узла назначения, на самом деле это не так, лишь исследуют топологию сети при помощи служебных сообщений и строят маршрутную таблицу, на каждом маршрутизаторе, а протокол IP лишь использует таблицу маршрутизации, для того что бы переслать пакет на нужный интерфейс
