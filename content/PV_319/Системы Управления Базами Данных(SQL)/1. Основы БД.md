База данных - это структурированный набор данных. Существуют различные БД которые для хранения используют, определенные модели данных. Наиболее распространёнными является Иерархическая модель данных, которая используется в Active Directory, Сетевая модель данных, Объектная модель данных, но наиболее распространённая на сегодня Реляционная модель данных (Relation - Отношение)
В Реляционной модели данных, они хранятся в виде связанных таблиц. Именно связи между таблицами и называют отношениями. В первые Реляционная модели данных, была описана в 1970 году Эдгаром Коддом, в документе "Реляционная модель данных, для больших банков данных совместного использования". Этот документ описывал основные концепции, Реляционных баз данных. Например такие как: То что абсолютно любые данных, должны хранится в базе, только один раз и никоем образом не должны повторятся, это достигается за счет нормализации данных. Так же абсолютно любые данные в базе должны быть уникальными. Уникальность каждой записи БД определяется Primary Key. А связи между таблицами, реализуются с помощью внешних ключей.
В Реляционной модели данных, столбики таблицы называют её полями, а строки записями

Как минимум одно поле таблицы должно быть уникальным, такое уникально поле и называют Primary Key(Первичный ключ). Первичный ключ, может быть простым, состоящим из одного поля или же составным состоящим из нескольких полей. Именно первичный ключ определяет уникальность каждой записи. Первичный ключ никогда и ни при каких обстоятельствах не может повторится, а если первичный ключ был удален из таблицы, то такой же первичный ключ больше никогда в ней не появится.
Внешний ключ (Foreign Key) - это поле, которое связывает одну таблицу с другой таблицей. Внешней ключ первой таблицы содержит значение первичного ключа второй таблицы, первая таблица зависит от второй таблицы. Вторая таблица в данном случае является определяющей (первичной), а первая зависимой(вторичной). Вынос повторяющихся данных в отдельную таблицу, называется нормализацией данных. Для нормализации данных, существуют нормальные формы, их всего пять.
Прежде чем создавать БД, её обычно проектируют, проект предусматривает из каких таблиц будет состоять база данных и как они будут между собой связанны. Для проектирования базы данных используют ERD - Entity Relation Diagram (Диаграмма сущность связь) на этой диаграмме каждая таблица представлена набором полей без данных
# Примечание
В маленьких таблицах, первичный ключ лучше всего задавать вручную, но в больших таблицах лучше всего включить autoincriment, что бы СУБД сама задавала значение первичного ключа, для записи. В ssms, это свойство называется Identity specification. Для него задаётся seed (начальное значение первичного ключа) и increment (шаг первичного ключа)

# Типы связей между таблицами
Таблицы в БД, могут быть связаны: 
1. 1 к 1(One-to-One) Example: (Officer-Gun, Car-Number, Human-Passport); 
2. Один ко многим(One-to-Many) Example: (Group-Students);
3. Многие к одному(Many-to-One) Example: (Students-Group);
4. Многие ко многим(Many-to-Many) Example: (Teachers-Disciplines);
5. Рекурсивная связь(Recursive Relation);
Many-to-Many всегда реализуется через промежуточную таблицу 
Рекурсивная связь это когда ссылается сама на себя, не посредственно или через другую таблицу
