[[CLR]] поддерживает три сценария взаимодействий:
1. Управляемый код может вызвать неуправляемые ф-ции из DLL, с использованием механизма P/Invoke (Platform Invoke). Многие типы, определяемые в FCL, во внутренней реализации вызывают ф-ции, экспортируемые из Kernel32.dll, User32.dll, etc;
2. Управляемый код может использовать готовые компоненты COM (Component Object Model, объектная модель компонентов) На основе библиотек типов из этих компонентов можно создать управляемую сборку с описанием компонента COM. Управляемый код обращается к типу из управляемой сборки точно так же как к любому другому управляемому типу.
3. Неуправляемый код может использовать управляемый тип. Большая часть существующего неуправляемого кода требует наличия компонента COM. Такие компоненты гораздо проще реализуются с управляемым кодом, что позволяет избежать служебного кода, связанного с подсчетом ссылок и интерфейсами
